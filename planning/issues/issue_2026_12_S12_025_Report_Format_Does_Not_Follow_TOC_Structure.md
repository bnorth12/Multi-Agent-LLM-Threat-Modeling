## Summary

The markdown report generated by agent_09 during the active run is poorly formatted and
does not follow the defined table of contents structure. Required sections are either
absent, malformed, or in an incorrect order relative to the expected report template.

This violates C10-A09-001, which requires the report to contain executive summary, scope,
boundaries, findings, mitigations, and residual risk sections in a consistent structure
suitable for governance and decision review.

For this issue scope, diagrams are handled by approved artifact references only; inline
diagram embedding in the report is intentionally deferred to a follow-on enhancement.

## Motivation

The report is a primary deliverable artifact. A malformed or unstructured report cannot
be used for program governance reviews, cannot be reliably parsed for downstream
conversion workflows (C10-A09-003), and cannot be validated by section-presence tests.
The table of contents structure also provides analyst-navigable anchors in the Markdown
viewer and in any PDF/HTML conversion output.

## Scope

### Prompt Engineering Defect

- Review the agent_09 system prompt and/or user prompt template to determine whether
  the required section headings and table of contents format are explicitly specified.
- Add or correct the prompt to require:
  - A leading table of contents with anchor links to each section.
  - Required sections in order: Executive Summary, Scope, System Boundaries,
    Threat Findings, Mitigations, Residual Risk, Appendices (optional).
  - Consistent H2 section headings (## Section Name) that match the table of contents
    entries exactly.
  - Threat findings presented in a structured format per threat (ID, name, STRIDE
    category, score, rationale, affected components, mitigations reference).
  - A diagram reference section or subsection that references approved diagram artifacts
    (or explicitly states none available) using stable artifact IDs/names.
  - Readability-focused markdown formatting rules (short paragraphs, consistent list
    formatting, and clear subsection labels) so governance reviewers can scan content
    without ambiguity.

### Diagram Handling Boundaries

- Include diagram references only for this sprint scope.
- Do not require embedded diagram rendering in the markdown report for this issue.

### Validation and Testing

- Add or update a section-presence test in the test suite that asserts all required
  section headings are present in a generated report artifact.
- The test should also verify the table of contents entries match the section headings.

### Report Viewer

- Verify the Markdown viewer (GUI-025) renders the corrected report with correct
  heading hierarchy and anchor navigation once the prompt is fixed.

## Acceptance Criteria

- [ ] Generated report contains a table of contents with links to each required section.
- [ ] Required sections are present: Executive Summary, Scope, System Boundaries,
      Threat Findings, Mitigations, Residual Risk.
- [ ] Section headings use consistent H2 (##) level and match table of contents entries.
- [ ] Threat findings section contains a structured entry per threat (ID, STRIDE, score,
      rationale, affected components, mitigations).
- [ ] Report references approved diagram artifacts only (no unapproved or missing
  diagram references).
- [ ] Report markdown formatting is readability-oriented: no malformed heading/list
      structures, no dense unbroken text blocks for core sections, and consistent
      subsection formatting across the report.
- [ ] Report passes section-presence automated tests.
- [ ] Report renders correctly with heading hierarchy in the Markdown viewer.
